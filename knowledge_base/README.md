# Knowledge Base

本目录以可维护知识文档为核心，
不以零散聊天记录为主。

目标是让读者快速获得可执行结论：
是什么、什么时候用、怎么做、怎么避坑、
以后还要补什么。

---

## 写作规范

新增或重构知识文档时，
优先参考：

- [Markdown 撰写格式指南](./Markdown撰写格式指南.md)

## 推荐骨架

常规知识文档建议按下面顺序组织：

1. `# 标题`
   主题清晰，避免泛化。

2. 开场说明
   简短说明“是什么”和“解决什么问题”。

3. `## 初始化流程` 或 `## 工作流程`
   给出整体顺序。

4. `## 常用概念`
   解释后文反复出现的术语。

5. 分步章节
   按流程展开配置、命令、参数或操作。

6. `## 完整示例` 或 `## 最小模板`
   给出可直接复用的最小路径。

7. `## 常见注意点`
   收敛高频错误和边界。

8. `## 速查`
   快速回忆关键入口。

9. `## 后续扩展复习点`
   保留生疏、疑问和未来要深入的内容。

---

## 写作原则

- 知识文档优先：
  强调稳定、可复用、可执行。

- 短而完整：
  每节聚焦一个问题，
  避免重复解释同一概念。

- 面向行动：
  优先提供流程、参数、示例和判断标准。

- 示例最小化：
  保留最小可用路径，
  避免超长样例淹没重点。

- 疑问不丢失：
  未展开的生疏点统一放入
  `后续扩展复习点`。

- 术语一致：
  同类概念在不同文档中保持同一叫法和结构。

---

## 内容质量检查

发布前检查：

- 能否在 1 分钟内看懂主题和用途。
- 是否有整体流程。
- 是否解释了核心概念。
- 是否有最小示例或模板。
- 是否包含关键避坑点。
- 是否有速查区。
- 生疏和疑问是否进入后续复习点。
- 代码围栏是否成对。
- 标题层级是否清晰。

---

## 维护约定

- 新文档默认对齐
  [Markdown 撰写格式指南](./Markdown撰写格式指南.md)。
- 已有文档优先做结构化，
  再补充细节。
- 草稿中的疑问不直接散落在正文，
  应移动到 `后续扩展复习点`。
- 当样板文档结构升级时，
  同步更新本 README 和撰写格式指南。
