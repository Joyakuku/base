目标是让读者快速获得可执行结论：是什么、何时用、怎么做、怎么避坑。

## 统一格式（推荐骨架）

建议所有知识文档按下面顺序组织：

1. `# 标题`（主题 + 可选“精简版”标记）
2. 开场两行：一句定义 + 一句边界/区别
3. `## 什么时候该用`（触发场景）
4. `## 常用命令 / 关键入口`（可选）
5. `## 放在哪 / 怎么组织`（路径、结构、分层）
6. `## 写什么最有价值`（高价值清单 + 最小模板）
7. `## 不建议写什么`（反例边界）
8. `## 中国用户特别注意`（环境差异、工具链、平台）
9. `## 常见坑`（3 条以内高频误区）
10. `## 推荐下一步`（相关文档跳转）

---

## 写作原则

- **知识文档优先**：强调稳定、可复用、可执行，不写聊天式长说明。
- **短而完整**：每节聚焦一个问题，避免重复解释同一概念。
- **面向行动**：优先提供条件、步骤、标准，而不是泛化背景。
- **示例最小化**：保留最小可用模板，避免超长样例淹没重点。
- **术语一致**：同类概念在不同文档中保持同一叫法和结构。

---

## 内容质量检查（发布前）

- 能否在 1 分钟内看懂“这篇文档解决什么问题”
- 是否明确“什么时候用 / 不该用”
- 是否给出至少一个可直接复用的最小模板
- 是否包含关键避坑点，且数量精简
- 是否与现有示例文档风格一致
