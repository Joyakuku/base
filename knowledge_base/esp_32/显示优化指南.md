# 显示优化指南

本指南聚焦 ESP32 平台上 OLED / LCD 显示性能的常见瓶颈与优化手段。
主要解决帧率不足、刷新闪烁、CPU 阻塞和内存带宽浪费等问题，
覆盖 SPI/I2C 传输优化、分块刷新、DMA 和双缓冲等方向。

典型上游场景：摄像头帧数据 → 显示（参见 [Camera 运用指南](Carmera运用指南.md)）。
目标硬件：SSD1306 / SH110x 系列 OLED（I2C/SPI），ST7789 / ILI9341 系列 LCD（SPI）。

---

## 工作流程

典型优化迭代顺序如下：

1. 确认当前刷新方式和瓶颈来源（整屏写入 vs 分块，CPU 轮询 vs DMA）。
2. 选型：根据场景选择分块刷新 / 差异刷新 / 双缓冲 / DMA 等策略。
3. 实施优化并测量帧率、CPU 占用和内存开销。
4. 权衡取舍：根据 PSRAM 余量、刷新质量和实时性要求决定最终方案。

## 常用概念

### 整屏写入

每次将显示缓冲区全体数据通过总线发送到屏幕。
实现最简单，但数据量大，适合静态内容或低分辨率场景。

### 分块刷新（Dirty Rectangle / Tile）

将屏幕分割为多个矩形区域（tile），
每次只将内容发生变化的区域写入屏幕。

核心思路：用少量 CPU 计算换取大量总线带宽的节省。

### 差异刷新（Frame Diffing）

维护前一帧的缓冲区副本。
每帧将新帧与旧帧逐字节比较，
仅写入发生变化的字节（或页）。

差异计算本身有 CPU 开销，
适合传输带宽是瓶颈的场景（如 I2C 低速模式）。

### DMA（Direct Memory Access）

外设直接从内存读取数据发送，
CPU 只需启动传输即可继续执行其他任务。

ESP32 的 SPI 支持 DMA，
I2C 不支持 DMA。

### 双缓冲（Double Buffering）

维护两个缓冲区：前缓冲（当前显示内容）和后缓冲（正在绘制的内容）。
绘制完成后交换两个缓冲区，
屏幕更新是原子操作，避免撕裂。

### 页对齐写入

SSD1306 等 OLED 控制器以页（8 像素行）为单位组织显存。
一次写入对齐到页边界可以减少命令开销和跨页处理逻辑。

## 1. 确定刷新瓶颈

在优化前先明确当前方案的瓶颈，
避免盲目套用复杂策略。

### 测量帧耗时

```c
#include "esp_timer.h"

int64_t start = esp_timer_get_time();
display_update(fb->buf, fb->width, fb->height);
int64_t elapsed = esp_timer_get_time() - start;
ESP_LOGI("perf", "Display update: %lld us", elapsed);
```

### 常见瓶颈判断

| 现象 | 可能瓶颈 | 推荐方向 |
|---|---|---|
| 总耗时 ≈ 传输耗时 | 总线带宽 | DMA、分块刷新 |
| 准备数据耗时长 | CPU 渲染 | 降低分辨率、预计算 |
| 屏幕出现撕裂线 | 无双缓冲 | 双缓冲 |
| 帧率不稳定 | 任务优先级 | 分块或异步刷新 |
| 更新时其他任务卡顿 | CPU 被刷新阻塞 | DMA、异步传输 |

### 估算总线传输时间

```text
传输时间 ≈ 像素总数 × 每像素位数 ÷ 总线频率

示例：
  128 × 64 单色 OLED
  SPI @ 8 MHz
  = 8192 bits ÷ 8,000,000 Hz
  ≈ 1 ms（不含命令开销）
```

## 2. SPI 传输优化

SPI 模式下屏幕刷新速度主要受时钟频率和传输方式制约。

### 提升 SPI 时钟频率

SSD1306 数据手册通常支持最高 ~10 MHz SPI 时钟。
ST7789 等 LCD 控制器可支持 40-80 MHz。

```c
spi_device_interface_config_t dev_cfg = {
    .clock_speed_hz = 10 * 1000 * 1000,  // 10 MHz，参考屏幕数据手册上限
    .mode = 0,
    .spics_io_num = CS_PIN,
    .queue_size = 1,
};
```

注意：

- 时钟频率不要超过屏幕数据手册规定的最大值。
- 飞线 / 面包板场景高频可能不稳定，
  降低到 4-6 MHz 可提高可靠性。

### 使用 SPI DMA

ESP32 的 SPI 驱动支持 DMA，
数据传输期间 CPU 可以执行其他任务。

```c
spi_device_interface_config_t dev_cfg = {
    // ... 其他配置
    .queue_size = 7,           // 增大队列，配合 DMA
};

spi_bus_config_t bus_cfg = {
    .mosi_io_num = MOSI_PIN,
    .miso_io_num = -1,         // 显示一般不需要 MISO
    .sclk_io_num = SCLK_PIN,
    .quadwp_io_num = -1,
    .quadhd_io_num = -1,
    .max_transfer_sz = 4096,   // 单次传输上限，DMA 场景可设大一些
};
```

配置项说明：

- `max_transfer_sz`
  DMA 单次传输的最大字节数。
  设得太小会导致数据被拆成多次事务，
  增大 CPU 中断开销。
  对 OLED（1 KB 级别）设为 `4096` 足够。

- `queue_size`
  SPI 事务队列深度。
  配合 DMA 使用时增大到 `7`，
  使得 CPU 可以提前提交多次传输。

### 合并 DC 命令与数据

对于需要区分命令/数据的 SPI 屏幕（如 ST7789），
每次 DC 切换都是一次额外事务。

将多次连续的数据写入合并为一次 SPI 事务：

```c
// 不推荐：每个像素区域分多次事务
for (int y = 0; y < H; y += 8) {
    set_addr_window(x, y, x + W - 1, y + 7);  // 事务 1：命令
    spi_transmit(data, W * 8);                 // 事务 2：数据
}

// 推荐：连续数据合并为一次事务
set_addr_window(x, y, x + W - 1, y + H - 1);
spi_transmit(data, W * H * bytes_per_pixel);
```

## 3. I2C 传输优化

I2C 模式下带宽更低（通常 400 kHz 或 1 MHz 快速模式），
优化重点是减少传输字节数和事务次数。

### 提升 I2C 时钟频率

```c
i2c_config_t i2c_cfg = {
    .mode = I2C_MODE_MASTER,
    .sda_io_num = SDA_PIN,
    .scl_io_num = SCL_PIN,
    .sda_pullup_en = GPIO_PULLUP_ENABLE,
    .scl_pullup_en = GPIO_PULLUP_ENABLE,
    .master.clk_speed = 400000,  // 标准快速模式 400 kHz
    // 部分屏幕在 1 MHz 下亦可稳定工作
};
```

注意：

- 1 MHz（Fast Mode Plus）需要屏幕和上拉电阻配合。
- 如果出现 I2C 超时或数据错误，先降回 100 kHz 验证是否因速度过快。

### 页对齐写入（SSD1306 I2C）

SSD1306 以 8 像素高的页组织显存。
一次发送一页（128 pixel × 8 pixel = 128 字节），
匹配硬件页边界，避免跨页寻址开销。

```c
// 推荐：逐页写入，每页 128 字节
#define SSD1306_PAGE_HEIGHT 8
#define SSD1306_WIDTH       128

for (int page = 0; page < SSD1306_HEIGHT / SSD1306_PAGE_HEIGHT; page++) {
    uint8_t page_start = page * SSD1306_WIDTH;
    // 发送页地址命令 + 一页数据（共 128 字节）
    ssd1306_send_page(page, &fb->buf[page_start], SSD1306_WIDTH);
}
```

### 差异刷新

仅将发生变化的字节写入屏幕，
在低速 I2C 下可显著减少传输量。

```c
static uint8_t prev_buffer[128 * 64 / 8];  // 前一帧副本

void display_update_diff(uint8_t *new_buf)
{
    for (int page = 0; page < 8; page++) {
        int page_offset = page * 128;
        // 找出本页变化范围
        int dirty_start = -1, dirty_end = -1;
        for (int col = 0; col < 128; col++) {
            int idx = page_offset + col;
            if (new_buf[idx] != prev_buffer[idx]) {
                if (dirty_start < 0) dirty_start = col;
                dirty_end = col;
            }
        }
        if (dirty_start >= 0) {
            // 仅写入变化区间
            ssd1306_send_partial_page(page, dirty_start,
                                      &new_buf[page_offset + dirty_start],
                                      dirty_end - dirty_start + 1);
        }
    }
    memcpy(prev_buffer, new_buf, sizeof(prev_buffer));  // 更新副本
}
```

以上示例表示：

- 维护一个 1 KB 的前帧副本（对 ESP32 内存开销极低）。
- 每帧逐字节比较，仅写入变化区间。
- 在静态内容为主的场景（如仪表盘），
  差异部分可能只有几十字节，
  传输时间从整屏的 ~20 ms 降至 ~1 ms。

### 减少 I2C 事务次数

每次 I2C 事务都有 START/STOP 和 ACK 开销。
将多次小写入合并为一次大写入：

```c
// 不推荐：逐字节写入，每字节一次事务
for (int i = 0; i < len; i++) {
    i2c_master_write_byte(cmd, data[i]);  // 128 次事务
}

// 推荐：整页一次事务
i2c_master_write_to_device(addr, data, 128, portMAX_DELAY);  // 1 次事务
```

## 4. 分块刷新策略

将屏幕分割为固定大小的 tile，
只更新发生变化的 tile。

### 固定分块（Tile-based）

```c
#define TILE_W 16
#define TILE_H 16
#define TILES_X (128 / TILE_W)   // 8
#define TILES_Y (64  / TILE_H)   // 4

static uint8_t tile_dirty[TILES_X * TILES_Y];  // 每个 tile 的脏标记

void mark_tile_dirty(int x, int y)
{
    int tile_x = x / TILE_W;
    int tile_y = y / TILE_H;
    tile_dirty[tile_y * TILES_X + tile_x] = 1;
}

void display_update_tiles(uint8_t *fb)
{
    for (int ty = 0; ty < TILES_Y; ty++) {
        for (int tx = 0; tx < TILES_X; tx++) {
            int idx = ty * TILES_X + tx;
            if (!tile_dirty[idx]) continue;

            // 仅刷新该 tile 区域
            display_write_tile(tx * TILE_W, ty * TILE_H,
                               TILE_W, TILE_H, fb);
            tile_dirty[idx] = 0;
        }
    }
}
```

配置项说明：

- `TILE_W` / `TILE_H`
  tile 尺寸。越小越精细（节省更多带宽），
  但 tile 管理开销越大。
  SSD1306 场景推荐 `16` × `16`，
  匹配页高度（8 的倍数）。

- `tile_dirty`
  脏标记数组。每次像素级绘制操作时设置对应 tile 的标记，
  刷新后清零。

### 自适应分块

如果帧间变化区域集中在小范围，
可以先计算实际变化区域的包围盒，
再只刷新包围盒。

```c
void display_update_bbox(uint8_t *new_buf)
{
    int x_min = 127, x_max = 0, y_min = 63, y_max = 0;

    for (int py = 0; py < 8; py++) {
        for (int col = 0; col < 128; col++) {
            int idx = py * 128 + col;
            if (new_buf[idx] != prev_buffer[idx]) {
                if (col < x_min) x_min = col;
                if (col > x_max) x_max = col;
                int y_base = py * 8;
                if (y_base < y_min) y_min = y_base;
                if (y_base > y_max) y_max = y_base;
            }
        }
    }

    if (x_min <= x_max) {
        display_write_region(x_min, y_min,
                             x_max - x_min + 1, y_max - y_min + 8, new_buf);
    }
}
```

适合场景：

- 固定分块：游戏、动画，变化分散在屏幕各处。
- 包围盒：仪表盘、文本更新，变化集中在局部区域。

## 5. 双缓冲

双缓冲消除撕裂，并允许渲染与传输并行。

### 基本实现

```c
static uint8_t *buf_a;  // 前缓冲
static uint8_t *buf_b;  // 后缓冲
static uint8_t *draw_buf; // 当前正在绘制的缓冲

void dbuf_init(void)
{
    buf_a = heap_caps_malloc(OLED_BUF_SIZE, MALLOC_CAP_SPIRAM);
    buf_b = heap_caps_malloc(OLED_BUF_SIZE, MALLOC_CAP_SPIRAM);
    draw_buf = buf_b;
}

void dbuf_swap(void)
{
    uint8_t *tmp = buf_a;
    buf_a = buf_b;
    buf_b = tmp;
}

void display_update_dbuf(void)
{
    // 将前缓冲写入屏幕（可配合 DMA 异步传输）
    display_write_full(buf_a);
}
```

工作流程：

1. 渲染代码始终向 `draw_buf`（后缓冲）写入。
2. 渲染完成后调用 `dbuf_swap()`。
3. 屏幕更新函数始终读取 `buf_a`（前缓冲），
   不受渲染过程中间状态影响。

注意：

- 双缓冲需要 2 倍帧缓冲内存。
  OLED 128 × 64 单色仅新增 1 KB，
  ST7789 240 × 240 RGB565 新增 115 KB，
  需确保 PSRAM 余量充足。

### 结合 DMA 实现异步刷新

```c
void display_update_async(void)
{
    // 启动 DMA 传输（非阻塞），CPU 在此期间可以继续渲染下一帧
    spi_transaction_t trans = {
        .tx_buffer = buf_a,
        .length = OLED_BUF_SIZE * 8,
    };
    spi_device_transmit(spi_handle, &trans);  // DMA 非阻塞
}
```

## 6. 渲染端优化

### 减少浮点运算

嵌入式场景避免在渲染循环中使用浮点数：

```c
// 不推荐：浮点计算
int x = (int)(sin(angle) * radius);

// 推荐：查表法
static const int sin_table[256];
int x = sin_table[(uint8_t)(angle_deg)] * radius / SIN_SCALE;
```

### 预计算常用值

```c
// 将屏幕划分相关的计算提到循环外
int stride = width;
int bytes_per_row = width / 8;
for (int y = 0; y < height; y++) {
    uint8_t *row = &buf[y * stride];    // 预计算行指针
    // ...
}
```

### 避免在刷新回调中分配内存

帧循环中的 `malloc` / `free` 会导致碎片化。
预分配所有缓冲区，
在初始化阶段完成内存分配。

## 常见注意点

### SPI DMA 传输期间修改源缓冲区

DMA 直接从内存读取数据到 SPI 外设。
如果在 DMA 传输期间修改源缓冲区（`buf_a`），
屏幕会显示一半旧数据一半新数据。
确保在 DMA 完成后再写入该缓冲区。

### I2C 传输超时

低速 I2C（100 kHz）下 128 × 64 整屏传输约需 20-30 ms。
如果在此期间被高优先级任务打断，
可能导致 I2C 超时。
考虑将显示刷新放在较低优先级任务中。

### 分块刷新导致命令开销大于数据节省

每个 tile 刷新需要额外的命令（设置列地址、页地址）。
如果 tile 太小（如 4 × 4），
命令开销可能超过实际数据量。
对 SSD1306 建议 tile 高度对齐到 8 像素（一页）。

### 差异刷新对全屏动画无效

当大部分屏幕内容都变化时（如视频流），
差异刷新的比较开销成为净损失。
此时应退回到整屏写入 + DMA。

### DMA 传输大小限制

ESP32 SPI DMA 单次传输有最大大小限制（受 DMA 描述符数量影响）。
对于大屏（如 320 × 240 RGB565 = 150 KB），
可能需要在驱动层拆分为多次 DMA 传输。

### PSRAM 缓存一致性

如果 frame buffer 位于 PSRAM，
DMA 读取前需确保数据已从 CPU cache 写回。
ESP-IDF 的 SPI 驱动会在内部处理此问题，
但如果使用自定义 DMA 方案，需手动调用
`Cache_WriteBack_Addr()` 相关函数。

## 速查

1. `spi_device_interface_config_t.clock_speed_hz`
   设置 SPI 时钟频率，直接决定传输带宽上限。

2. `spi_bus_config_t.max_transfer_sz`
   DMA 单次传输上限，设太大会被驱动拆分。

3. `i2c_config_t.master.clk_speed`
   I2C 时钟频率，影响低速总线的刷新帧率。

4. `esp_timer_get_time()`
   微秒级计时，用于测量帧耗时瓶颈。

5. `heap_caps_malloc(size, MALLOC_CAP_SPIRAM)`
   从 PSRAM 分配大缓冲区，释放内部 DRAM。

6. `ssd1306_write_page(page, data, len)`
   页对齐写入，匹配 SSD1306 的页寻址模式。

7. `display_write_region(x, y, w, h, buf)`
   区域写入，分块刷新和包围盒方案的基础接口。

8. `Cache_WriteBack_Addr(addr, size)`
   手动写回 CPU cache，在 PSRAM + 自定义 DMA 场景使用。

## 后续扩展复习点

1. LVGL 集成优化
   LVGL 框架自带脏区域跟踪和双缓冲，
   学习如何配置 `LVGL_DISPLAY_RENDER_MODE` 减少手写优化代码。

2. 水平滚动与垂直滚动的硬件支持
   SSD1306 支持硬件垂直滚动，
   ST7789 支持硬件水平滚动，
   可实现零带宽的滚动效果。

3. ST7789 的 tear-effect 和 TE 引脚
   研究 TE（Tearing Effect）信号线如何配合 VSYNC 消除撕裂，
   以及 spi_device_interface_config_t 中的 `input_delay_ns` 如何配置。

4. 多屏并发刷新
   当一个 ESP32 驱动多个屏幕时，
   如何调度 SPI 事务避免总线仲裁延迟。

5. FreeRTOS 任务优先级与刷新延迟
   研究显示刷新任务在不同优先级下的最差延迟，
   以及如何用 `xTaskAbortDelay` 和信号量精准控制帧间隔。
